* **Tools:** I used Google Gemini to help structure my `README.md` documentation, review my sentinel loop logic, and check edge-case test scenarios for `min_max.cpp`.
* **One decision:** When designing the loop to read integers until `-99`, I needed a clean way to initialize `smallest` and `largest` from actual data while also detecting when no valid numbers were entered. I decided to use a boolean flag (`bool hasData = false;`) alongside a priming read (`std::cin >> currentNumber;`). Inside the `while (currentNumber != SENTINEL)` loop, checking `if (!hasData)` allowed me to overwrite `smallest` and `largest` with the very first valid input and set `hasData = true`, while also using `if (hasData)` after the loop to decide whether to print the extrema or the no-data message.
* **A specific check:** I tested the all-negative series `-8, -3, -12, -99` in OnlineGDB. Before running, I calculated that the smallest value should be `-12` and the largest should be `-3`. The program output `Smallest: -12` and `Largest: -3`, which confirmed two critical things: overwriting `smallest` and `largest` on the first iteration (`!hasData`) with `-8` prevented the initial `0` declaration from falsely remaining as the largest value, and placing `std::cin >> currentNumber;` at the end of the loop kept `-99` from overwriting `-12`.
* **Learning:** I can now write a sentinel-controlled `while` loop using a priming read and a boolean state flag to track minimum and maximum values across positive, negative, and single-value datasets.
